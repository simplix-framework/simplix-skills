# Documentation of the Java frameworks

Each repository keeps its own standard and its own checks. This skill names where they are and the rules that are checked by machine, so a change is written to pass them.

## SimpliX

Read `simplix:scripts/docs/documentation-guidelines.md` before creating or changing a document, and `simplix:scripts/docs/documentation-templates.md` for the page shape of each kind of document.

| Rule | Meaning |
| --- | --- |
| Reader first | A document answers one question of a developer who uses the framework. It is one of introduction, getting started, guide, reference, concepts, troubleshooting |
| Two languages | Every document exists in English and Korean with the same headings, code blocks and figures |
| Locations | The introduction pair at the root of the repository and of each module; pages under `docs/en` and `docs/ko`, and under the same folders of a module |
| File names | Lowercase with hyphens, the same name in both languages |
| Figures | SVG files drawn by the modules of the figures folder, one per language; no diagram written as a code block |
| Release lines | A requirement that differs between the lines is a table with a row per line; no patch version is written |
| Examples | Commands and output come from a real run; names are copied from the source |
| Coverage | The documents of a module cover every class, annotation attribute and property a user touches |
| Symbols | Only ✔ ✖ ⚠ ℹ; no emoji and no em dash |

Checks, run from the root of the repository:

```bash
node scripts/docs/validate-docs.mjs --strict          # structure, language parity, links, images, symbols
node scripts/docs/validate-code-sync.mjs              # the documents against the code
node scripts/docs/validate-doc-coverage.mjs --strict  # public types, properties and methods the documents never mention
./scripts/build-docs.sh && node scripts/docs/validate-docs.mjs --site   # links of the built site
```

- A check takes a module name to narrow it. All of them end without a finding before a document change is reported as done.
- Figures are built and verified as `simplix:docs/figures/README.md` says. An SVG is never edited by hand.
- When code is added or changed, the documents that describe it change in both languages in the same change.
- The Korean pages follow `simplix:GLOSSARY.md`.
- A change to the documents goes to both release lines, as the repository's rule for its lines says.

## Searchable JPA

Read `searchable-jpa:docs/en/documentation-guide.md`. Its Java, HTTP and JSON listings come from files the test suite compiles and runs, so a listing is changed in its source file and not in the page.

```bash
npm run test:docs        # listings, coverage of features, parity of English and Korean
```

Figures are generated by the modules beside the settings file `searchable-jpa:scripts/figures/document-figures.json`.

## Both

- The site of a repository is built from its documents by its own workflow. The shell, the header and the sidebar are shared with the other SimpliX sites; `simplix:docs/en/contributing-to-the-docs.md` says where the shared files are and how they are copied.
- A document states the final state. It does not tell how the text got there.
